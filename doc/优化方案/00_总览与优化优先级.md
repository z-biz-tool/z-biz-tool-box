## 0.2 项目独特价值（为什么值得单独优化）

z-biz-tool-box 与其它 z-biz-tool 子项目最大的不同在于它是一个**平台**而非单一功能应用：

1. **浮层式即时唤起**：`⌥Space` / `⌃⌘K` 全局快捷键唤起 Spotlight 风格浮层，用完即隐（[`../../src-tauri/src/lib.rs`](../../src-tauri/src/lib.rs) 第 39-63 行；关闭改为隐藏不退出，第 66-75 行）。对标 Raycast / Alfred / uTools 的“呼出即用”理念。
2. **双层工具体系**：
   - **内置工具**：源码即插件，`src/plugins/<group>/<Name>.tsx` 放文件即自动注册（[`../../src/plugins/_registry.tsx`](../../src/plugins/_registry.tsx) 用 `import.meta.glob(eager:true)` 收集），当前 31 个工具（编码 6 / 文本 9 / 加密 4 / 转换 7 / 网络 2 / 系统 3）。
   - **外部插件**：`~/.z-biz-tools/plugins/<id>/` 下 `plugin.json + main.html`，通过 iframe 沙箱加载，宿主注入 `window.zBiz` 受限 API（[`../../src/plugins/external/PluginIframe.tsx`](../../src/plugins/external/PluginIframe.tsx)、[`../../src/plugins/external/api.ts`](../../src/plugins/external/api.ts)）。
3. **去中心化插件市场**：用户自配 base URL 市场源，`GET {base}/list` 拉列表、按 id 拼下载地址（[`../../src/plugins/external/market.ts`](../../src/plugins/external/market.ts)、[`../../docs/market-spec.md`](../../docs/market-spec.md)），无需中心服务器。
4. **AI 可生产的插件规范**：`_SKILL/插件开发/` 是给 AI 阅读的插件开发说明书（[`../../_SKILL/插件开发/SKILL.md`](../../_SKILL/插件开发/SKILL.md)），降低造工具门槛。

> 平台属性决定了它的核心风险面是**“执行第三方代码”**：安全与隔离是第一优先级，其次才是功能与性能。

## 0.3 立即处理项（P0，安全底线）

以下 4 项为**已确认缺陷**（证据见 [01](./01_现状审计与问题清单.md)），触及“执行第三方代码”的安全底线。**2026-10-19 轮已全部落地**，括号内是当前的落地形态与证据位置：

- **P0-1 关闭 TLS 证书校验** ✅ **已修复**。原先硬编码 `.danger_accept_invalid_certs(true)`（[`../../src-tauri/src/plugin_engine.rs`](../../src-tauri/src/plugin_engine.rs)）。现为**缺省校验证书**，放宽必须由调用方**逐次显式**传 `security.insecure=true`，且响应回带 `insecure` 标记供 UI 标黄。前端还多了一道「允许不安全连接」设置开关（默认关）+ 工具内的勾选框（默认不勾），**放宽需两步**。
- **P0-2 远程插件无完整性校验** ✅ **已修复**。安装流程现为「先下载 + 校验，再落盘」：下载 `main.html` 的**原始字节**算 SHA-256，与 `/list` 条目的 `sha256` 比对，**不一致拒绝安装且一个字节都不落盘**（[`../../src/plugins/external/installer.ts`](../../src/plugins/external/installer.ts)、[`../../src/plugins/external/hash.ts`](../../src/plugins/external/hash.ts)）。明文 `http://` 源改为**默认拒绝**，需显式开关放行（[`../../src/plugins/external/market-security.ts`](../../src/plugins/external/market-security.ts)）。
- **P0-3 iframe 沙箱过宽 + 无 CSP** ✅ **已修复**。沙箱现为 `allow-scripts allow-forms allow-modals allow-popups`，**不含 `allow-same-origin`** ⇒ 插件文档处于**不透明源**（[`../../src/plugins/external/bridge-protocol.ts`](../../src/plugins/external/bridge-protocol.ts)）。应用级 CSP 从 `null` 改为实际策略，并另配 `devCsp`（[`../../src-tauri/tauri.conf.json`](../../src-tauri/tauri.conf.json)）。
- **P0-4 插件无权限模型** ✅ **已修复**。manifest 声明式权限（`permissions`）+ 默认拒绝 + **API 按权限裁剪**（[`../../src/plugins/external/api-gate.ts`](../../src/plugins/external/api-gate.ts)）+ 敏感能力首次调用用户确认（[`../../src/plugins/external/permission-prompt.ts`](../../src/plugins/external/permission-prompt.ts)）。

> ⚠️ 这 4 条的**代码与判据**都已落地并验证；但**真实 GUI 窗口里的交互未在本机实测**（无显示环境），
> 详见 [08 的「未实测项」](./08_本轮深度优化实施记录.md#85-未实测项据实说明不含糊)。

## 0.5 核心原则（贯穿全部文档）

1. **插件沙箱隔离**：第三方插件运行在最小权限沙箱内，不能触达宿主 DOM / localStorage / Tauri 命令，除非通过受控桥接。
2. **来源可校验**：远程插件必须可验证完整性与来源（哈希 / 签名 / HTTPS），拒绝静默信任。
3. **危险操作需确认**：卸载、覆盖、递归删除、对外发起请求等破坏性/敏感动作需显式用户确认。
4. **Agent 不自动执行破坏操作**：任何 AI/Agent 辅助只产出建议或需人确认的动作，绝不自动执行删除、覆盖、外发数据等破坏性操作。
