# 03 · 技术架构与性能优化

> 状态：设计方案，未实现；基线 `84aa094`；当前事实 = 静态代码证据，指标 = 拟定验收目标。

本文给出架构与性能的**推荐方案**，覆盖：插件架构与隔离沙箱、加载性能与懒加载、插件 API 契约与版本兼容、工具注册机制、状态管理、跨工具通信。所有指标为拟定目标（假设见 [06](./06_测试验收与风险清单.md)）。

## 3.1 插件架构与隔离沙箱

**现状**：外部插件在 iframe 中加载 `asset://localhost` 映射的本地 `main.html`（[`../../src/plugins/external/scanner.ts`](../../src/plugins/external/scanner.ts) 第 65-67 行 `convertFileSrc`），宿主经 postMessage 桥接注入 `zBiz`（[`../../src/plugins/external/PluginIframe.tsx`](../../src/plugins/external/PluginIframe.tsx) 第 40-91 行）。sandbox = `allow-scripts allow-forms allow-same-origin allow-popups`（第 162 行）。

**推荐**：
1. **收紧 sandbox**：去掉 `allow-same-origin`，让插件运行在 opaque origin（跨源桥接本就走 postMessage，不依赖同源）。若某些插件确需同源存储，用宿主代理的 `zBiz.storage` 而非放开同源。目标 sandbox：`allow-scripts allow-forms allow-popups`（按需再加）。
2. **桥接方法白名单化**：当前 `onMessage` 用 `method.split(".").reduce` 在 `api` 对象上任意寻址（[`../../src/plugins/external/PluginIframe.tsx`](../../src/plugins/external/PluginIframe.tsx) 第 58-63 行），等于把整个 zBiz 对象图暴露给字符串反射。改为显式 `switch(method)` 白名单 + 参数 schema 校验。
3. **进程/资源隔离**：为 iframe 增加数量上限与卸载策略（切换工具即卸载上一个 iframe，避免多插件常驻内存）。
4. **CSP**：给插件页与宿主都加 CSP（见 [04](./04_数据安全与可靠性.md) 4.6），`tauri.conf.json` 的 `"csp": null` 改为白名单策略。

## 3.2 加载性能与懒加载

**现状**：`_registry.tsx` 用 `import.meta.glob([...], { eager: true })` 一次性打包约 28 个内置工具（[`../../src/plugins/_registry.tsx`](../../src/plugins/_registry.tsx) 第 51-54 行），含 37.6KB 的 JsonTool。外部插件每次启动串行重扫（[`../../src/plugins/external/store.ts`](../../src/plugins/external/store.ts) 第 12-31 行）。

**推荐**：
1. **元数据与组件分离**：`import.meta.glob(eager:true)` 只加载**轻量 meta**（key/label/icon/keywords），组件改为 `React.lazy(() => import(...))` 动态分包。meta 用于列表/搜索（首屏必需），组件在选中时才拉。
2. **路由级代码分割**：Vite 手动分包，把 antd、图标库、大工具（JsonTool/HashTool）拆到独立 chunk。
3. **外部插件扫描缓存**：把上次扫描结果 + 各 `plugin.json` 的 mtime 持久化，启动先渲染缓存、后台增量校验（mtime 变了才重读）。串行 IO 改 `Promise.all` 并发。
4. **iframe 预热（可选）**：对最近使用的外部插件预热一个隐藏 iframe，降低首开延迟。

**目标（拟定，假设中等规模 30 内置 + 10 外部插件，中端 macOS）**：浮层首屏可交互 ≤ 300ms；单工具打开 ≤ 150ms（内置懒加载 chunk）；启动扫描缓存命中时 ≤ 50ms。

## 3.3 插件 API 契约与版本兼容

**现状**：`zBiz` API 定义在 [`../../src/plugins/external/api.ts`](../../src/plugins/external/api.ts) 第 13-36 行，manifest 无版本协商字段（[`../../src/plugins/external/types.ts`](../../src/plugins/external/types.ts) 第 30-47 行）。宿主升级 API 后旧插件可能静默失效。

**推荐 API 契约（新增 `apiVersion` 协商）**：

```jsonc
// plugin.json（manifest）建议新增字段
{
  "id": "com.example.demo",
  "name": "示例插件",
  "version": "1.2.0",
  "zbizApi": "1",                 // 插件要求的宿主 API 主版本
  "permissions": ["clipboard.read", "clipboard.write", "http", "storage", "notify"],
  "features": [ /* 不变 */ ]
}
```

```ts
// 桥接握手建议：hello 携带 apiVersion，宿主回 ready 时给出兼容范围
// 插件 → 宿主
{ "__zbiz_hello": 1, "apiVersion": "1" }
// 宿主 → 插件（兼容则注入，不兼容则拒绝并给出提示）
{ "__zbiz_ready": 1, "pluginId": "...", "hostApiVersion": "1", "granted": ["clipboard.write","storage"] }
```

**版本策略**：语义化，主版本不兼容时宿主拒绝加载并提示“插件需要 zBiz API vX，当前宿主为 vY”；次版本只增不改，向后兼容。`zBiz` 对象挂 `zBiz.apiVersion` 供插件运行时探测。

**IPC 契约收敛（postMessage 协议）**：把现有 `{__zbiz, id, method, args}` / `{__zbiz_rsp, id, result, error}` 正式写成协议文档，并：
- `method` 走白名单枚举（不再字符串反射）。
- `args` 按方法做 schema 校验（如 `http_request` 校验 url 协议、method 枚举）。
- 响应端 `postMessage` 的 `targetOrigin` 由 `"*"`（[`../../src/plugins/external/PluginIframe.tsx`](../../src/plugins/external/PluginIframe.tsx) 第 34 行）改为已知插件源。

## 3.4 工具注册机制

**现状**：内置工具靠路径 glob 自动注册（[`../../src/plugins/_registry.tsx`](../../src/plugins/_registry.tsx) 第 113-134 行），group 由目录派生（第 107-111 行）；外部工具靠 scanner 扫目录。两条注册链彼此独立，`ALL_TOOLS` 只含内置。

**推荐**：
1. **统一 ToolDescriptor**：内置与外部都归一为同一 `ToolDescriptor`（id/kind/label/group/icon/keywords/run），Spotlight/QuickOpen/tray/搜索只消费这一份模型，消除 [`../../src/_shared/Spotlight.tsx`](../../src/_shared/Spotlight.tsx) 第 79-133 行里内置/外部两套拼装逻辑的重复。
2. **注册即校验**：注册时校验 key 唯一性、icon 合法性、group 存在性，冲突显式报错（当前只 `console.warn` 跳过未知 group，[`../../src/plugins/_registry.tsx`](../../src/plugins/_registry.tsx) 第 119-122 行）。
3. **tray 注册闭环**：App 挂载后把启用的 ToolDescriptor 分组序列化推给 `register_tools`（[`../../src-tauri/src/lib.rs`](../../src-tauri/src/lib.rs) 第 84-87 行），修复 D6。

## 3.5 状态管理

**现状**：单一 `uiStore`（zustand + persist）承载主题/收藏/最近/输入/禁用/市场源（[`../../src/stores/uiStore.ts`](../../src/stores/uiStore.ts) 第 62-160 行）；外部插件用非持久 `extStore`（[`../../src/plugins/external/store.ts`](../../src/plugins/external/store.ts)）。

**推荐**：
1. **关注点分离**：把 `marketSources`（含 cachedList，可能很大）从 `uiStore` 拆到独立 `marketStore`，避免每次 UI 变更都序列化大缓存到 localStorage。
2. **persist 版本迁移**：`uiStore` 的 persist 无 `version`/`migrate`（[`../../src/stores/uiStore.ts`](../../src/stores/uiStore.ts) 第 147-158 行），schema 变更会静默错位。加 `version` + `migrate`。
3. **`inputs` 体积治理**：所有工具输入都塞进一个 `inputs` 全量持久化（第 88-89 行），大文本（如 JsonTool 粘贴几 MB）会撑爆 localStorage。建议按工具设上限 + LRU 淘汰。

## 3.6 跨工具通信

**现状**：无显式机制（见 [02](./02_产品能力与交互优化.md) 2.4）。

**推荐**：在 `uiStore` 之外新增一个轻量 `pipeStore`：
```ts
interface PipePayload { from: string; to: string; mime: string; text: string; ts: number }
// setPipe(payload) → 目标工具挂载时 consumePipe(to) 读取并清空
```
内置工具直接读写；外部插件通过 `zBiz.pipe.receive()`（需 `pipe` 权限）经桥接获取，绝不把管道数据默认广播给未授权插件。

## 3.7 工程结构

**现状**：[`../../src/_shared/MarketView.tsx`](../../src/_shared/MarketView.tsx) 约 61.8KB 单文件，与 [`../../src/plugins/system/PluginMarket.tsx`](../../src/plugins/system/PluginMarket.tsx) 职责重叠（两处都做远程安装/版本对比）。`../../src/agent/` 为死代码（D8）。

**推荐**：
- 拆分 MarketView 为 `MarketList / MarketCard / useMarketInstall` 等子模块，安装/版本对比逻辑抽到单一 service，供两处复用。
- 移除或隔离 `../../src/agent/`（与工具箱无关的 SQL Agent 占位）。
- 统一网络出口：内置工具全部走 `invoke('http_request')` 或统一封装，杜绝裸 `fetch`（D11，[`../../src/plugins/convert/ExchangeRate.tsx`](../../src/plugins/convert/ExchangeRate.tsx) 第 73 行）。
