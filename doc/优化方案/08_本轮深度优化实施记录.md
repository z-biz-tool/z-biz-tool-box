### 8.2.2 T1.9 · API 按权限裁剪（新增第二道闸）

**问题**：此前只有**协议层**一道闸（`parseRpc` 拒越权包）。协议层防的是**恶意包**，
但防不住宿主自己新增的调用路径——任何一处新的内部代码只要握着 api 对象，
不判权限就能拿到能力。

**做法**：新增 `src/plugins/external/api-gate.ts`（纯逻辑，可直接断言），
`buildZbizApi(pluginId, perms)` 现在**必填**权限集（漏传 → 响亮地抛错，绝不静默全放行），
返回的是**按权限裁剪过的 API 表面**：

- 被拒方法返回 `{ ok: false, error: "PermissionDenied: ..." }`（有信封的方法）
  或抛 `Error("PermissionDenied: ...")`（`invoke` 这类无信封的）
- **被拒时绝不触碰底层实现** —— 这一点由「会记账的假实现」直接断言（`tests/api-gate.test.ts`）
- 裁剪后的对象 `Object.freeze`，运行期换不掉实现

**接线**：权限集**必填**这件事由 `npm run check:bridge` 的源码断言守住
（`buildZbizApi` 若忘了传 perms，门禁就形同虚设，而 `api-gate` 自己的单测仍然全绿）。

### 8.2.3 T2.1 / T2.2 · zBiz 协议版本协商

- `plugin.json` 新增 `zbizApi` 字段；**不写按 `"1"` 处理**（台账兼容条款）
- 主版本号比较：`plugin > host` ⇒ 加载期直接拒绝并说明「请升级宿主」
- 解析不出主版本号 ⇒ **拒绝**（放行等于让未知的协议形态进来）
- 握手包：`hello` 带 `apiVersion`；`ready` 回 `hostApiVersion` + `granted`（插件能自查拿到了什么）
- 裁决放在**加载期**（`scanner.ts`）而不是握手期 —— 握手期拒绝会让插件一直转圈，
  加载期标成 `error` 用户在列表里一眼能看见「为什么不工作」

### 8.2.4 T1.7 · 安装前确认

顺序被重新排成：**取 manifest → 算清单 → 用户确认 → 下载主文件 → 校验 → 落盘**。

- 权限清单只存在于 `plugin.json` 里（市场条目里没有权限字段），
  所以必须先取 manifest；`installer.ts` 拆出 `fetchRemoteManifest()` 与 `installRemotePlugin()`
- 清单展示台账要求的 5 项：插件名 / 来源 URL / 版本 / 完整性校验情况 / 权限清单
- 源没给 `sha256` ⇒ **警告但不阻断**（台账灰度条款），且界面如实标「未校验」

### 8.2.5 T2.6 · 敏感能力首次调用确认

- 纯状态机在 `src/plugins/external/permission-prompt.ts`：允许 / 拒绝 / 始终允许
- 「允许」「拒绝」**只在本次运行内**有效；「始终允许」跨会话（落 `localStorage`）
- 决定**按插件 + 方法隔离**（`pluginId:method[:cmd]`）—— A 插件的授权不放行 B 插件
- `readClipboard` 与 `invoke:http_request` 需要确认；其它方法不问

### 8.2.6 T1.3 / T2.7 · CSP 与 connect-src 收敛

`tauri.conf.json` 的 `"csp": null` 改成了实际策略，并**另配 `devCsp`**：

| 指令 | 值 | 理由 |
| --- | --- | --- |
| `default-src` | `'self'` | 收紧基线 |
| `script-src` | `'self'` | 生产不许 inline / eval |
| `style-src` | `'self' 'unsafe-inline'` | antd CSS-in-JS 注入 style 标签 |
| `img-src` | `'self' data: blob: asset: http://asset.localhost https:` | 内联图、截图、插件 logo、市场远程图标 |
| `connect-src` | `'self' ipc: http://ipc.localhost https://open.er-api.com data:` | **只放已知域名**：全仓只有两处浏览器 fetch（汇率 API、截图 data URL），其余网络访问走 Rust |
| `frame-src` | `asset: http://asset.localhost` | 外部插件 iframe |
| `object-src` | `'none'` | 不加载对象类资源 |
| `base-uri` / `form-action` | `'self'` / `'none'` | 防注入 / 钓鱼 |

`devCsp` 额外放行 `script-src 'unsafe-inline' 'unsafe-eval'` 与 `localhost:5173` 的 ws —
**vite 的 react-refresh 会注入 inline script，HMR 走 websocket**，生产策略会把 dev 弄挂。

### 8.2.7 T1.1 / T1.6 · 两个安全开关（默认值改到安全的一侧）

| 开关 | 存哪 | 缺省 | 效果 |

### 8.2.8 T2.8 · `http_request` 改异步

原先是 `pub fn`（同步 command）：`reqwest::blocking` 会在 command 线程上一直等到响应回来
（最长 30s），**一次慢请求能把整个应用卡住 30 秒**。改成
`pub async fn` + `tauri::async_runtime::spawn_blocking`，阻塞 IO 挪到 blocking 线程池。

「不阻塞主线程」没法在单测里直接测，所以用**源码契约断言**把它钉住
（`include_str!` 读自己的源文件，断言 `pub async fn http_request` 与 `spawn_blocking` 都在）。

### 8.2.12 cron 工具的三个真缺陷（上一轮修，本轮随提交入库）

`src/plugins/convert/CronParser.tsx` 原先的三个缺陷：

1. `parseField` 收 `_min`/`_max` 却**从不校验** ⇒ `0 99 * * *` 被描述成「第99分钟」
2. 「下次运行时间」是 `now + N 分钟`（**假 cron 语义**），且界面未展示 ⇒ 死代码
3. `a-b/n` 的**步长被静默吞掉**

本轮把 cron 的纯逻辑抽到 `src/plugins/convert/cronLogic.ts`
（`.tsx` 无法被 `node --experimental-strip-types` import，要测的判定逻辑必须落在 `.ts` 纯逻辑模块），
并新增 `tests/cron.test.ts`（27 条）。**界面行为不变**（修正后的 `nextRuns` 仍不展示）。

## 8.3 变异反向验证：26 条，**26 条全部咬住**

判据必须证明自己「咬得住」——否则「测试全绿」只是没被检验过的同义词。

- 脚本：`/tmp/box_mutation.py`（结果：`/tmp/box_mutation_result.json`）
- 纪律：**每条变异之前先还原**（内存字节快照 + sha256 校验，不用 git —— 工作区有未提交改动）；
  判定只看「测试是否失败」这个**事实**（退出码），不断言失败形态 ——
  失败可能是 `AssertionError`，也可能是 `TypeError`，只认前者会漏判；
  编译失败 / 语法错 = **没咬住**

      M01..M26  BITTEN  26/26
      [restore] 全部文件已还原, sha256 校验通过

**首轮 26 条里有 4 条没咬住，逐条查了根因**（不是「判据不敏感」就完事）：

| 编号 | 现象 | 真因 | 处置 |
| --- | --- | --- | --- |
| M11 | 权限来源改成"空"却全绿 | **变异本身无效**：只加了个类型标注，运行期语义完全相同 | 换成真变异（`rawPerms` 直接清空） |
| M13 | always/session 顺序反了却全绿 | **变异没写到点子上**：`session.get()` 无副作用，把 `always.has()` 挪到它前后**行为完全一样** | 改成把 always 检查挪到 `decided === "deny"` **之后** |
| M17 | `allowInsecure` 改成 truthy 检查却全绿 | **判据不敏感**：原判据只覆盖 `undefined` / `{}`（都是 falsy），两者表现一样 | 补判据：truthy 非 true 的值（`1` / `"yes"` / `{}` / `[]`）也必须被拒 |
| M20 | 当前版本的数据被当成老数据却全绿 | **判据不敏感**：原判据只测「当前版本 + 干净值」，经迁移分支后布尔值还是同一个布尔值 | 补判据：当前版本 + **脏值**（`"yes"` / `1`）必须原样保留 |

M17 / M20 补完判据后复跑，**26/26 全部咬住**。

## 8.8 菜单栏（tray）功能轮（2026-10-25）：**菜单栏入口整条链是断的**

起因：家族探针扫「后端注册的命令 vs 前端有没有入口」（见 lead 台账第八节（9））
⇒ box 有 5 个注册命令前端一次都没调 ⇒ 逐个看，发现其中两个是**核心功能断链**。

### 8.8.1 P0：tray 菜单永远是占位组「加载中…」

- Rust 侧 `register_tools` 的注释一直写着「**前端 mount 时调用**，把当前启用的工具分组推给 Rust 构建 tray 菜单」
  —— 但前端**从来没调过**。
- `create_tray` 在 groups 为空时会建一个占位组「加载中…」
  ⇒ 菜单栏里**永远只有「加载中…」**，一个工具都没有。
- 这个 app 的**全部界面就是菜单栏**（菜单栏工具箱）⇒ 这不是边角功能，是主链路。

### 8.8.2 P0：Rust 点菜单项，前端根本收不到

- Rust 点某个工具会 `app.emit("select-tool", key)`，前端 `listen` 了吗？
  **没有** —— 全仓搜 `select-tool` 只有 Rust 侧那一处。
- ⇒ 就算菜单里有条目，点下去也只是唤起主窗口，**不会切到那个工具**。
- ⇒ 两段都断：**没有分组、没有接收**。

### 8.8.3 修法

- 新增 `src/trayBridge.ts`：`pushTrayTools(disabled)` 是「推分组给 Rust」的**唯一出口**
  （只推启用中的工具；空分组不推；推失败不抛 —— tray 是锦上添花，不能带崩主窗口）。
  放一个模块是因为**两处**都要用：App 挂载时推一次、装完兄弟应用后再推一次
  （tray 的「兄弟应用」子菜单是 Rust 侧扫出来的，不推就还是装之前的状态）。
- App.tsx：挂载/禁用项变化时 `pushTrayTools`；并 `listen("select-tool")` → 切到对应工具。
- BrothersView：安装完成（`brother-install-progress` 的 `done` 相）后 `pushTrayTools()`。

### 8.8.4 顺带把两个「只有后端、没有界面」的命令处理掉

| 命令 | 处置 | 理由 |
|---|---|---|
| `greet` | **删** | Tauri 模板脚手架示例（`Hello, {}! Welcome to z-biz-tool-box`），零调用者、零价值 ⇒ 整个 `commands.rs` 一并删掉 |
| `refresh_brother_tools` | **删** | 接线后**完全冗余**：`register_tools` 每次都会重扫兄弟状态并重建整张菜单；而「重新扫描」这个交互**本来就有**（兄弟应用面板的「重新检查更新」按钮走 `brother_overview(force=true)`） |
| `log_dir_path` | **换成 `open_log_dir`** | 原来只返回路径、前端从不调 ⇒ 用户看得见「前端在写日志」却找不到日志在哪。现在用**本仓已经装好的** `tauri-plugin-opener` 打开目录并把路径一并返回（不自己 spawn 系统命令 ⇒ 跨平台一致），设置面板「关于」区加了「打开目录」按钮 |
| `get_state` | **保留，登记为预留** | 调试用的只读命令（主窗口 visible/focused/minimized）。纯只读零副作用 ⇒ 留着不构成风险；已写进契约测试的「预留未接线」清单并写明理由 |

### 8.8.5 新增尺子：`tests/ipcContract.test.ts`（7 例）

博采众长：把 db / note 这轮验证过的 IPC 契约门搬过来，**再加一条家族其它仓还没有的**：

1. 前端 invoke 的命令，后端必须真的注册了；
2. 插件桥层白名单（`ALLOWED_INVOKE_COMMANDS`）里的命令，后端必须真的注册了
   （桥层是**动态** invoke，命令名是变量 ⇒ 静态扫不到，只能按白名单核）；
3. 后端注册的命令，要么被前端调用，要么在「预留未接线」清单里写明理由；
4. ⭐ **Rust emit 的每个事件，前端必须 listen** —— 这条才是抓住本次 P0 的门：
   Rust 发了 `select-tool`、前端没监听 ⇒ 事件发出去没人收 ⇒ 界面毫无反应；
5. 专门钉住 tray 链路（`register_tools` 被调 + `select-tool` 被听）。

**变异验证**（证明咬得住，不是摆设）：
- 把 `listen("select-tool")` 改成 `listen("select-tool-REMOVED")` ⇒ **2 条用例变红**；
- 把 `invoke("register_tools")` 改成 `invoke("register_tools_DISABLED")` ⇒ **3 条用例变红**；
- 改回去 ⇒ 全绿。
