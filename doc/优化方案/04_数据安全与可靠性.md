# 04 · 数据安全与可靠性

> 状态：设计方案，未实现；基线 `84aa094`；当前事实 = 静态代码证据，指标 = 拟定验收目标。

本文聚焦工具箱作为**插件平台**的安全核心：第三方代码在用户桌面执行，一旦被恶意利用，后果包括数据窃取、权限提升、供应链攻击。覆盖：沙箱与权限隔离、来源校验与签名、危险操作确认、数据隔离、Agent 边界、Tauri 权限收敛、供应链。

## 4.1 插件沙箱与权限隔离

### 现状证据

| 维度 | 现状 | 证据 |
| --- | --- | --- |
| 运行环境 | iframe，`sandbox="allow-scripts allow-forms allow-same-origin allow-popups"` | [`../../src/plugins/external/PluginIframe.tsx`](../../src/plugins/external/PluginIframe.tsx) 第 162 行 |
| API 桥接 | `window.zBiz` 通过 postMessage 注入（跨源时走 RPC 桥） | [`../../src/plugins/external/PluginIframe.tsx`](../../src/plugins/external/PluginIframe.tsx) 第 40-67 行 |
| API 范围 | 全量能力无条件授予：clipboard.read/write、http_request、storage、notify、hide/showWindow | [`../../src/plugins/external/api.ts`](../../src/plugins/external/api.ts) 第 40-101 行 |
| 方法寻址 | `method.split(".").reduce` 反射，任意路径可达 zBiz 对象图 | [`../../src/plugins/external/PluginIframe.tsx`](../../src/plugins/external/PluginIframe.tsx) 第 58-63 行 |
| manifest 权限声明 | 不存在 | [`../../src/plugins/external/types.ts`](../../src/plugins/external/types.ts) 第 30-47 行 `ExternalPluginManifest` 无 permissions |

### 风险

1. **`allow-same-origin` + `allow-scripts` 组合**：MDN 明确警告同时设置这两项"allows the embedded page to remove the sandbox attribute"（虽然现代浏览器已堵此具体攻击，但原则上同源 + 脚本仍使隔离弱化）。插件若通过 `asset://localhost` 加载，与其它同协议插件同源，可能互相读取。
2. **无权限声明 → 全量信任**：安装一个插件等于授予它读剪贴板、对外发 HTTP（任意 URL，含内网 SSRF）、操作主窗口。用户无感知。
3. **反射方法寻址**：如果 `api` 对象原型链上有非预期属性，反射可触达（当前 zBiz 对象是纯数据，风险有限，但不排除未来扩展引入危险方法）。

### 建议方案

1. **最小权限 sandbox**：`sandbox="allow-scripts allow-forms allow-popups"`（去掉 `allow-same-origin`）。验证插件是否仍需 same-origin（大概率不需要，因为桥接走 postMessage）。
2. **manifest 声明式权限 + 安装时授权**：
   - manifest 新增 `permissions: string[]`（如 `["clipboard.read","http","storage"]`）。
   - 安装 UI 展示权限清单（类似手机应用权限弹窗），用户确认才写入。
   - `buildZbizApi` 根据 granted 权限**裁剪**返回对象：未授权的 method 不存在或调用时抛 `PermissionDenied`。
3. **桥接方法白名单**：显式枚举允许调用的 method 路径，不再 `reduce` 反射。

## 4.2 插件来源校验与签名

### 现状证据

- 安装流程（[`../../src/plugins/external/installer.ts`](../../src/plugins/external/installer.ts) 第 87-140 行）：`downloadText(pluginJsonUrl) → JSON.parse → validateManifestAgainstEntry（只校 id/name/features 存在性）→ downloadText(mainHtmlUrl) → writeTextFile`。全程无 hash、无签名验证。
- 市场列表（[`../../src/plugins/external/market.ts`](../../src/plugins/external/market.ts) 第 218-256 行 `validateList`）做了 schema 校验（id 唯一、id 合法字符、icon 仅 http(s)），但 **不校验内容完整性**。
- 市场源允许 `http://`（[`../../src/plugins/external/market.ts`](../../src/plugins/external/market.ts) 第 51 行），明文传输。

### 风险

- 攻击者控制 HTTP 中间人 → 篡改 `main.html` → 用户下次打开插件执行恶意代码。
- 市场源被入侵 → 批量投毒所有安装用户。
- 无审计溯源：安装后无法判断文件是否被本地修改。

### 建议方案

1. **最低方案（P0，快速落地）**：市场列表 `/list` 每个 entry 增加 `sha256` 字段（对 main.html 内容的 SHA-256）。installer 下载后计算哈希，不一致则拒绝安装。
2. **进阶方案（P1）**：插件包改为 `.zip`（或 `.tar.gz`），列表提供整包 hash + 签名（Ed25519）。宿主内嵌公钥验签。
3. **源可信度**：
   - 默认仅允许 `https://`（内网开发可显式"允许不安全源"开关，UI 红色警告）。
   - 市场源可附加 `fingerprint`（TLS 证书指纹 / 公钥），安装时校验。
4. **本地篡改检测**：scanner 读 plugin.json 时可选计算 mtime + hash，若与安装记录不一致，标记"已修改"并提醒用户。

### 建议方案

1. **安装确认层（P0）**：安装前弹出摘要对话框（插件名、来源 URL、版本、权限列表、hash 指纹），用户确认后才开始下载。
2. **敏感 API 首次调用确认（P1）**：`clipboard.read`、`http_request` 首次由某插件调用时，弹一次"允许/拒绝/始终允许"。决策持久化到 `uiStore`。
3. **破坏性操作双确认**：若未来 Agent 可触发卸载/覆盖，必须二次人工确认（见 4.5）。

## 4.4 数据隔离

### 现状证据

- 插件 storage 使用宿主 localStorage，key 前缀 `zBiz.plugin.<id>.`（[`../../src/plugins/external/api.ts`](../../src/plugins/external/api.ts) 第 38-41 行）。前缀由宿主控制，插件通过桥接调用，**不能自行拼前缀越权**。
- 宿主 `uiStore` 也存 localStorage（[`../../src/stores/uiStore.ts`](../../src/stores/uiStore.ts) 第 147-158 行，name = `z-biz-tool-box-ui`）。
- iframe `allow-same-origin` 使插件保留 `asset://localhost` 源。宿主源为 `tauri://localhost`（或 dev 时 `http://localhost:5173`）。跨源，插件不能直接访问宿主 localStorage。

### 风险

- 若去掉 `allow-same-origin`（建议），插件变为 opaque origin，无法使用 `localStorage`（连自己的也不行）。这意味着插件必须通过 `zBiz.storage` 桥接来持久化，当前设计已走桥接，**去 same-origin 后反而更安全**。
- 多插件共用 `asset://localhost` 源：如果保留 `allow-same-origin`，同源插件可互相读 localStorage（虽然它们不该直接存数据在那，因为 storage 走桥接）。建议验证是否有插件直接操作 `localStorage`。

### 建议

- 去掉 `allow-same-origin` 后，验证所有现有插件仍正常工作（storage 走桥接，无影响）。
- 在桥接层强制 key 前缀隔离（当前已有，保持），并加 namespace 容量上限。

## 4.5 Agent 不可自动执行破坏性操作

### 现状

- **当前无真实 Agent 能力**（[`../../src/agent/AgentManager.ts`](../../src/agent/AgentManager.ts) 全为 TODO，见 [01](./01_现状审计与问题清单.md) D8）。
- 但代码里有 `invoke` 能力暴露给前端，若未来 Agent 接入可直接调 Tauri 命令。

### 红线规则（设计约束，未来 Agent 必须遵守）

1. Agent **禁止**自动调用：`uninstall_plugin`、`writeTextFile`（覆盖）、`writeFile`（覆盖）、`remove_dir_all`。
2. Agent **禁止**自动发起 `http_request`（POST/PUT/DELETE）到非白名单 URL。
3. Agent 产出的破坏性动作（删/改/外发）必须以 **"建议"** 形式展示给用户，用户显式确认后才执行。
4. Agent 对 `zBiz.storage` 只能写自己 namespace 的数据，不能改宿主 store。
5. Agent 执行链最长 3 步无确认即暂停，要求用户 review。

### 落地方式

- 在 `api.ts` / invoke 层增加 `caller` 标记（`user` | `agent`）。
- `caller=agent` 时，破坏性命令自动拦截并返回 `{ needConfirm: true, action: {...} }`。
- 前端展示确认 UI，用户同意后以 `caller=user` 重发。

## 4.6 Tauri 权限收敛

### 现状证据

[`../../src-tauri/capabilities/default.json`](../../src-tauri/capabilities/default.json) 第 8-49 行授予主窗口：
- `core:default` + window show/hide/focus/unminimize/start-dragging
- `clipboard-manager:default`（读写剪贴板）
- `dialog:default`（文件对话框）
- `fs:default` + mkdir/write-text-file/write-file/read-dir/read-text-file/exists
- `fs:scope` 限定 `$HOME/.z-biz-tools/**`
- `shell:default`（打开外部 URL/目录）
- `http:default` 放行 `http://**:*` + `https://**:*`（全部地址）
- `global-shortcut:allow-register/unregister/is-registered`

[`../../src-tauri/tauri.conf.json`](../../src-tauri/tauri.conf.json) 第 36-42 行：
- `"csp": null`（无 Content-Security-Policy）
- `"assetProtocol": { "enable": true, "scope": ["$HOME/.z-biz-tools/**"] }`

### 风险

- **http 全放行**：webview 内任何 JS（含 iframe 插件通过桥接转发）可请求任意地址，SSRF 面大开。
- **shell:default**：允许 `open` 命令打开 URL/文件，虽限 `shell:default` 不含 exec，但 open 可打开 `file:///` 或自定义协议（潜在钓鱼面）。
- **无 CSP**：webview 内无 inline-script / connect-src 限制，若宿主页存在 XSS 入口则攻击者自由执行。

### 建议

1. **http 收敛**：capability 改为白名单模式，只放行已知市场源域名 + 内置工具需要的域名（如 `open.er-api.com`）。或改用 Rust 端代理，按 pluginId + 用户授权做请求过滤。
2. **CSP 配置**：`tauri.conf.json` → `"csp": "default-src 'self'; script-src 'self'; connect-src 'self' https://open.er-api.com; img-src 'self' asset: https:; style-src 'self' 'unsafe-inline'"`。按实际需求调整，核心是限制 `connect-src` 和 `script-src`。
3. **shell 收敛**：如果只需打开文件夹，改用 Tauri command 包装 `opener` 并限定 scope（只允许打开 `~/.z-biz-tools/plugins`），而非全量 `shell:default`。
4. **关闭 `danger_accept_invalid_certs`**：`http_request` 改为默认验证证书；仅在用户显式配置"允许不安全连接"时关闭（UI 红色警告 + 日志记录）。

## 4.7 供应链风险

### 攻击面分析

```
用户添加市场源 URL
    ↓
GET {url}/list → 拉取 MarketList JSON（schema 校验 ✅，但无签名 ❌）
    ↓
用户点击安装
    ↓
GET {url}/plugins/{id}/plugin.json → 写盘（无 hash ❌）
GET {url}/plugins/{id}/main.html → 写盘（无 hash ❌，可执行代码 ❌）
    ↓
iframe 加载 main.html → 执行第三方 JS
    ↓
zBiz API 全量暴露（clipboard、http、storage ❌）
```

每一环都缺乏信任校验。如果市场源被入侵或中间人攻击，用户立即被 fully compromised。

### 综合建议（按实现难度递增）

| 阶段 | 措施 | 难度 |
| --- | --- | --- |
| P0-a | installer 下载后计算 SHA-256，与 `/list` 中 `sha256` 字段比对 | 低 |
| P0-b | 市场源默认只允许 HTTPS，HTTP 需显式开关 + 红色警告 | 低 |
| P0-c | 安装前弹窗展示来源 + 权限 + hash，用户确认 | 低 |
| P1-a | 插件包改 zip，整包 hash + Ed25519 签名，内嵌公钥验签 | 中 |
| P1-b | 本地篡改检测：scanner 校验 mtime/hash 与安装记录 | 中 |
| P2 | 市场源 TLS 证书指纹固定（certificate pinning） | 高 |
| P2 | 插件沙箱运行时审计（记录 http/clipboard 调用日志，可审查） | 中 |

## 4.8 可靠性

### 错误隔离（🟢 已有）

- 单插件 scanner 失败不拖垮全局（[`../../src/plugins/external/scanner.ts`](../../src/plugins/external/scanner.ts) 第 45-88 行 try/catch）。
- 市场源 fetch 失败保留旧 cachedList（[`../../src/plugins/external/market.ts`](../../src/plugins/external/market.ts) 第 276-303 行"永远不抛异常"）。
- iframe `onLoad` 注入失败走 postMessage 桥接兜底（[`../../src/plugins/external/PluginIframe.tsx`](../../src/plugins/external/PluginIframe.tsx) 第 70-84 行）。

### 可靠性缺口

| 缺口 | 影响 | 建议 |
| --- | --- | --- |
| iframe 内 JS 崩溃宿主无感知 | 白屏无反馈 | 增加 heartbeat / error event 上报 |
| `http_request` Rust 端是 blocking | 30s timeout 阻塞调用线程 | 改 async（tokio）或限制并发 |
| 无全局错误边界 | React 组件崩溃白屏 | 加 ErrorBoundary |
| persist localStorage 损坏 | 全部偏好丢失 | 加 version/migrate + 初始化校验 |
| 无崩溃日志 | 用户报 bug 无凭据 | Rust panic hook + 前端 window.onerror 写文件 |
